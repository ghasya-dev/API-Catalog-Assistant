# API Catalog Assistant

A deterministic, grounded Fastify/TypeScript assistant for querying an API catalog and assessing OpenAPI specifications against the supplied quality rubric.

## Why this design

Catalog facts and rubric checks are handled with code rather than generated by an LLM. This makes answers reproducible, testable, inexpensive, and resistant to hallucination. Natural-language support uses intent patterns and catalog-aware matching; ambiguous requests return clarification instead of guessing.

## Requirements

- Node.js 20+
- npm

## Run

```bash
npm install
npm run typecheck
npm run scenarios
npm start
```

The server listens on `http://localhost:3000` by default.

## Endpoints

- `GET /health`
- `GET /catalog/apis?domain=Payments&status=production`
- `GET /catalog/apis/:name`
- `GET /quality`
- `GET /quality/:name`
- `POST /assistant/query`

Example:

```bash
curl -X POST http://localhost:3000/assistant/query \
  -H 'content-type: application/json' \
  -d '{"question":"Which payment APIs are production-ready?"}'
```

## Quality scoring

The 12 supplied rubric rules are evaluated across documentation, security, design/consistency, and completeness/reliability. Severity weights are:

- low: 1
- medium: 2
- high: 4

The score is `passed weight / total weight * 100`. Reports include rule-level evidence and concrete fixes.

## Scenario results

Run `npm run scenarios`. Results are written to `results/scenario-results.json` and include the interpreted intent, grounded response, execution time, and self-assessment.

## Notes

This implementation intentionally does not require an API key or external LLM. A production extension could add an LLM only as a constrained intent parser while retaining deterministic tools as the source of truth.
